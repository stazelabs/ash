# ASH-112 — `ash replay` ledger-as-regression-suite (first cut)

## Task

Ship `ash replay`: re-run prior ledger calls against the current build and
report per-verb token deltas vs the originals. Unblocks ASH-108 (cache
envelope) measurement and gives every Tier 1 token-saving claim an empirical
scoreboard.

## Verbs used / added

- Added `ash replay` (read-only meta-verb; dispatches in-process via a Deps
  closure over the live runner + pretty registries, just like `ash bench`).
- Used: `ash help`, `ash find`, `ash grep`, `ash read`, `ash edit`,
  `ash write` (heredoc form), `ash test`, `ash stop`, `ash replay` itself.

## Scope (this ship)

- `--session current|all|<id>` + `--since <dur>` + `--verb <verb>` +
  `--limit N` + `--regress_tokens %` + `--top N`.
- Skip rules: mutating verbs (write/edit/init/uninit/stop), heavy verbs
  (test/bench), recursive (replay), `args_truncated` (the `<truncated:N>`
  sentinel ashd writes for long string args), `no_args`/`decode_failed` for
  verbs that need args.
- Pretty output: totals line + per-verb table + ok-mismatches + top
  regressors. Same regression flag semantics as `ash bench`
  (`|Δtok%| > regress_tokens`).
- Smoke output from this session — replay across all sessions, 39/50
  replayed, correctly flagged one regression: a `read` of
  `internal/verbs/verbs.go` grew +265 tokens (+12.3%) after I added the
  new runner block. That's *literally the change I just made*. The
  regression detector works.

## Deferred / out of scope

- **File-state snapshots / git-ref pinning.** Replay runs against the
  current working tree; results diverge if files changed since the
  recorded call. ASH-112's description mentions this as future work.
- **CI integration.** The wire result has the structure CI needs
  (Overall.Regressions, OKMismatch) but no Make target / GitHub action
  wiring yet.
- **Persistence.** Bench writes runs to `bench_runs` / `bench_case_results`;
  replay returns its result ephemerally. Could mirror that pattern later
  if trend lines on replay results turn out to matter.
- **Replaying mutating verbs.** No `--include_mutating` flag. write/edit
  args are 1024-byte-capped in the ledger sanitizer anyway, so honest
  replay isn't possible for content-heavy calls without a separate
  args-storage scheme.

## Friction encountered

- The `cat << EOF | ash write --content -` pattern the CLAUDE.md gotcha
  suggests fails the PreToolUse hook — bash `cat` denies as `Bash:cat`
  regardless of whether stdout is piped or redirected. The hook strips
  heredoc bodies from segment text but `cat` itself is still the first
  token and lands on the deny list. Workaround that works: drop `cat`
  entirely and feed the heredoc directly into `ash write`:
  ```
  bin/ash write --path FILE --content - <<'EOF'
  ...
  EOF
  ```
  The hook sees only `bin/ash write` in that segment — heredoc body is
  invisible. Consider updating the CLAUDE.md gotcha example to show
  this form rather than `cat ... | ash write`.

- `UPDATE_GOLDEN=1 ash test ...` didn't propagate the env to `go test`.
  `ash test` doesn't set `cmd.Env`, so the subprocess inherits the
  daemon's env, not the client's. Worked around by editing
  `cmd/ash/testdata/usage_golden.txt` directly via `ash edit`. Small
  follow-up: `ash test` could plumb env through, or accept `--env`.
