# 2026-05-07 — Ship 4: `ash grep`

## Task

Build `ash grep`: RE2 pattern search across one file or a tree, with smart-case, fixed-string, word-boundary, files-only, and surrounding-context modes; reuse `find`'s walk semantics (gitignore, hidden-dir skip, exclude, max_depth, glob); silently skip binaries and oversized files. Wire through the daemon, client, and help registry.

## Verbs used

`ash grep` (heavy), `ash find` (a few), `ash metrics` (post-smoke). The harness Edit/Read/Write was the development substrate; bash for `go build`, `go test`, and `pkill` of the stale daemon.

## Friction

1. **Stale daemon respawn theatre.** Before smoke-testing, I tried to kill any leftover `ashd` process and check it was gone with `pgrep -af ashd`. The `-f` flag makes pgrep match the full command line, so `pgrep -af ashd` matches *its own argv*. Result: every iteration looked like the daemon was respawning under a new PID. Wasted four minutes. Lesson: in shell smoke-tests, `pgrep -x ashd` (exact name match) is what I want; `-f` lies. Worth a session-runbook note for future debugging.

2. **Test fixture vs smart-case (caught the design, lost the test).** First `TestRun_FilesOnly` and `TestRun_GlobFilter` runs failed because I'd written them with `Case: "smart"` and `Pattern: "Foo"`, then asserted that all `foo`/`FOO`/`Foo` files would match. Smart case correctly switched to *case-sensitive* on the uppercase pattern, so half the fixture files dropped out. Diagnosis was instant; fix was changing the test's `Case` field to `insensitive` to match the assertion. Same family of mistake as ship 2's path-form-in-tests bug: tests fought the design instead of testing it. Worth keeping an eye on; may signal that test-helpers should default to a single mode and force the test to be explicit when it deviates.

3. **No grammar nicety in the first PrettyResponse.** First smoke test printed `1 files`. Trivial fix (one `plural` helper), but the lesson is that human-debug pretty-print is exactly where the agent's dignity-check still kicks in — even if humans aren't the primary user, lazy plurals make the whole verb feel half-finished. Worth catching at PR time, not after.

4. **find/grep walker duplication.** ~70 lines of `filepath.WalkDir` filtering (gitignore, exclude, hidden, max_depth, symlink-skip) is now copy-pasted between `find.go` and `grep.go`. The session note for ship 2 already flagged "extract a shared walker at three users." We're at two; ship 5 (whatever that is) is the trigger to extract `internal/verbs/walker`. Calling it out explicitly now so the next agent doesn't paper over by adding a *third* copy.

## Workarounds

- For the daemon-respawn confusion: switched to `ps aux | grep -i ashd | grep -v grep` to list real processes, and just trusted the smoke test results once a fresh `pkill -9 -x ashd` succeeded.
- For the test fixture bug: kept the smart-case tests (`TestRun_SmartCaseLowercaseGoesInsensitive`, `TestRun_SmartCaseUppercaseGoesSensitive`) as the explicit semantics check, and reframed the file-filter tests with `Case: "insensitive"` so the case dimension was held constant.

## Suggestions

In rough priority order:

- **Extract the shared walker.** `find` and `grep` now run identical walk/filter code — gitignore loading, hidden-dir skip, max_depth, exclude doublestar match, symlink-skip. A `internal/walker.Walk(root, opts, fn)` that yields `(path, fs.DirEntry)` for every accepted leaf would absorb both verbs and unblock `stat`-with-filters cleanly. Aim for ship 5 or sooner if a third walker user (say, a `--list_files` mode) lands first. The shape: `Opts{Glob, Exclude, MaxDepth, IncludeHidden, RespectGitignore, FollowSymlinks}` plus a `Yield(path, dirEntry) (skipDir bool, abort bool)` callback.

- **Token-count the per-line text.** `ash grep --pattern 'package' --path . --max_matches 5` returned 173 tokens — almost all of it the line text itself, not the metadata. As `MatchCount` grows, line text dominates `tokens_out`. We currently report `tokens_out` honestly via `cl100k_base`, but we should think about whether the verb itself should offer a `--text false` flag (return only `path:line:col`, drop `text`) for "I just want to know where, I'll `read` to see what." That's effectively a structured `rg -l` plus line numbers, which agents probably want often.

- **`--multiline` mode.** Today line-by-line search means `pattern: '^func.*\n.*return'` cannot match. Multiline + `(?s)` is a small addition: search whole-body (we already read it) instead of per-line; emit one Match per leftmost-longest hit with the *first* line as the record line. Defer until a session actually wants it.

- **Default-include leaf dotfiles in walks.** A user grep'd `--pattern 'TODO' --path . --files_only true` and got `CLAUDE.md`. But `.gitignore` was excluded (hidden-leaf-dot-file rule for descent vs leaf is consistent for find — both find and grep skip hidden *directories* but include hidden leaf files). Confirmed correct via the `find_test.go::TestRun_DefaultsFindAllNonHidden` precedent. No action needed; just making sure we don't drift.

- **Glob is matched against path-relative-to-walk-root.** Worth documenting in `--help` more explicitly. Today the description says "matched against the path relative to --path" for find but only "files matching this are scanned" for grep. Will tighten in a follow-up doc pass.

- **Cold-start tax persists.** Same observation as ship 2 — first call after fresh daemon is 5-10ms slower than warm calls because of tiktoken lazy BPE init. Pre-warm in `ledger.NewCounter`. Now a recurring TODO.

Observations:

- **Tokens-out per match record runs ~17-22 tokens** for the canonical pretty form (`  LINE: TEXT` plus per-file header). For 16 matches in 8 files (call 1) that was 437 tokens. Ripgrep's default text output for the same query lands in the same ballpark — we're not paying a structure tax over `rg`. The win is that the agent does no parsing.
- **`--files_only` is the cheapest mode for cardinality.** Call 7 returned 1 file at 21 tokens out. Compare to a full match search of the same pattern that would emit per-line records with line text. When the next step is `ash read`, files-only is the right shape.
- **The truncation hint adds ~25 tokens** when triggered. Worth it — without it the agent has to remember the cap from the help page.
- **Bad regex returns in 5µs.** RE2 compile is the dominant factor in normal calls (microseconds of overhead at most); the verb is filesystem-bound for any non-trivial walk.
- **No binary or oversized-file hits in this smoke.** Need to verify in a subsequent session against a tree with binaries (e.g. `bin/`-as-included scenario) that the skipped counters render nicely in the pretty header.

Aggregate: 11 calls, all OK except the deliberate bad-regex test, no `LedgerError`. Wire format stable.
