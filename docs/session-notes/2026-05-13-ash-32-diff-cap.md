# 2026-05-13 — ASH-32: profile and raise the diff LCS cap

## Task

Resolve ASH-32: profile the `internal/diff` LCS implementation at 2000/4000/8000/16000 lines and decide whether to raise the cap, swap the algorithm, or just improve the error message.

## Verbs used

- `ash read`, `ash grep`, `ash find`, `ash edit`, `ash write`, `ash test`, `ash help`

## Profile

Wrote a temporary `diff_perf_test.go` that called an internal cap-free `linesLCS` helper at four sizes, both worst-case (every line differs) and realistic (~1% lines differ, contiguous). darwin/arm64, Go 1.26.1.

```
=== worst case (every line differs) ===
n=2000   wall=9ms     alloc=7 MiB
n=4000   wall=39ms    alloc=30 MiB
n=8000   wall=155ms   alloc=122 MiB
n=16000  wall=657ms   alloc=489 MiB
=== realistic (~1% lines differ, contiguous) ===
n=2000   wall=9ms     alloc=7 MiB
n=4000   wall=37ms    alloc=30 MiB
n=8000   wall=154ms   alloc=122 MiB
n=16000  wall=605ms   alloc=489 MiB
```

Realistic vs. worst-case is essentially identical — the DP table dominates regardless of how much of it ends up on the LCS path. Memory is the binding constraint, scaling cleanly O(n²) as expected (uint16 table, 8 bytes/cell with overhead).

## Decision

- 4000 lines = ~30 MiB, ~40ms — well inside the ticket's "few hundred ms / 64 MiB" envelope.
- 8000 lines = ~120 MiB, ~155ms — crosses the memory envelope.
- 16000 lines = ~490 MiB — nope.

Raise `MaxLines` from 2000 → 4000. Skip the Myers / sergi-go-diff swap: the cap bump alone covers ~2x more real-world files at modest cost, and adding a dep for the long tail isn't worth it at this stage. Refactored `Lines()` into a one-line public cap-check + an internal `linesLCS` helper so future profiling (or a Hirschberg-style `--stat` fast path) has a clean seam.

Improved the `too_large` error message:

```
diff inputs too large: a=<m>, b=<n> (max <cap> lines/side); reduce input size or split the file
```

Both side counts now visible in one message. Considered suggesting `--stat true` per the ticket, but `--stat` currently runs the same `Lines()` call and inherits the same cap — would be a lying suggestion.

## Friction

- The PreToolUse hook blocked harness `Read`, then blocked harness `Edit` (which requires a prior harness `Read`). CLAUDE.md already warns about this for `Write`; same issue applies to `Edit`. Used `ash read` + `ash edit` instead — both worked fine.
- `ash test --verbose true` shows pass/fail per test but doesn't surface `t.Logf` output, even on passing tests. To get the profile numbers I had to write them to `/tmp/ash-diff-perf.txt` from the test and `ash read` it back. Would be nice to have a flag that streams Go's `-v` output verbatim, or at least a `--show-logs` toggle.

## Suggestions / follow-ups

- **`--stat` fast path** (potential follow-up ticket): cheapest correct stat is LCS-length-only via two rolling rows, O(min(m,n)) space. With that, `--stat` can drop the cap entirely (or carry a far higher one), and the `too_large` error can honestly recommend it. ~20 LOC.
- **`ash test` log streaming**: currently `t.Logf` lines are dropped on PASS even with `--verbose true`. Useful for ad-hoc profiling.
