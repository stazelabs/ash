# ASH-104 — `ashmcp` MCP server binary

**Task.** Ship `cmd/ashmcp/`, the MCP server adapter from the
ASH-104..ASH-107 adoption pivot. v1 surfaces eight read-side verbs as MCP
tools to any harness that speaks stdio MCP (Claude Code, Claude Desktop,
Cursor, ...) — the build-out that decouples ash adoption from the
PreToolUse hook.

**Verbs used.**
- `ash write`, `ash edit`, `ash read`, `ash find`, `ash grep`, `ash help`
  for code authoring/inspection inside this repo.
- `ash test`, `ash report` for verification and ledger introspection.
- `go build` / `go mod tidy` for dependency wiring (bash whitelist).

**Implementation summary.**
- New binary `cmd/ashmcp/` with three files: `main.go` (entry, server
  setup, embedded-schema bootstrap), `dispatch.go` (per-call UDS
  roundtrip, args decoding, response shaping), `daemon.go` (dial-or-start
  copied from `cmd/ash/main.go` — see "Friction").
- Embeds the schema artifact via `//go:embed tools.json`. Because Go
  embed cannot reach outside the package directory, the canonical
  artifact stays at `docs/mcp/tools.json` and a byte-identical copy lives
  at `cmd/ashmcp/tools.json`. `cmd/ashschema` was extended to write both
  on `gen` and verify both on `check` — drift is now caught by the same
  `make schema-check` gate that already existed.
- v1 surface: `ash_read`, `ash_find`, `ash_grep`, `ash_stat`, `ash_git`,
  `ash_report`, `ash_metrics`, `ash_help`. Writes (`write`, `edit`,
  `diff`) deferred to phase 2 per the ticket.
- Dependency: `github.com/modelcontextprotocol/go-sdk v1.6.0` (pure Go;
  transitively pulls jsonschema-go, uritemplate, segmentio/encoding,
  golang-jwt, oauth2 — all pure Go).
- Test surface: parse-and-shape unit tests plus an in-memory transport
  test (`TestServerRegistersTools`) that runs a real `mcp.Client` against
  a real `mcp.Server` to verify the advertised tool set matches
  `readSideVerbs` exactly.

**Verification.**
- `make all` builds three binaries.
- `bin/ash test` — 39 packages pass, including `cmd/ashmcp`.
- `make schema-check`, `make vocab-check` — both ok.
- Smoke test: spawned `bin/ashmcp` from a small Go program using
  `mcp.CommandTransport`, called `tools/list` (returned the expected 8
  tools), then `tools/call ash_grep` with `pattern=ASH-104 path=.` —
  succeeded with `IsError=false`, decoded JSON `data` containing the
  match list. `ash report --since 5m` confirms the grep landed in the
  ledger like any CLI call.

**Friction.**
- **No `mkdir` allowance for new package layout.** Creating
  `cmd/ashmcp/` worked because `bin/ash write` creates parent
  directories implicitly, but discovering that took a moment. Not
  worth a verb change; pulling the fact into this note for future
  reference.
- **`//go:embed` reach-out-of-package limitation.** Hit immediately
  when the obvious `//go:embed ../../docs/mcp/tools.json` failed. The
  pattern restriction is well-documented Go semantics, not an ash
  issue — solved by teaching `cmd/ashschema` to write both paths and
  checking both into git. The duplication is gated end-to-end so it
  cannot silently drift. The alternative (gitignore the embed copy
  and generate at build time) was rejected because it would break
  `go test ./...` from a fresh clone before `make schema` runs.
- **`cmd/ashmcp/daemon.go` duplicates `cmd/ash/main.go` dial-or-start
  logic.** Kept the duplication on purpose per CLAUDE.md
  "Don't add abstractions beyond what the task requires" — extract
  when a third caller appears (next harness adapter, or an HTTP
  transport for `ashmcp`). The duplication is ~120 LOC including
  `killStaleIfNeeded`, `findAshd`, `tailLog`, `isConnRefused`,
  `isENOENT`. Worth flagging here so the next person who touches
  either copy can confirm both stay in sync.
- **`ash edit --old - --new -` is rejected — only one arg can read
  from stdin.** Hit when trying to do a stdin-piped diff edit in a
  single call. The error message is clear; switching to a literal
  `--old` value worked. Not a bug.

**Suggestions.**
- Phase-2 follow-up: surface `write`/`edit`/`diff` once stdio MCP
  behavior is observed on real harness sessions (ASH-104 scope was
  explicit that writes wait). The schema artifact already covers them,
  so it's a one-line `readSideVerbs` change plus tests.
- ASH-107 (adoption docs) should now be unblocked — the snippet for
  `~/.claude.json` / Claude Desktop is a 5-line MCP server config
  pointing at `bin/ashmcp` (no args).
- Eventually extract `daemonclient` to `internal/daemonclient/` if and
  only if a third caller materializes. Don't pre-extract.

**Instrumentation.** The smoke-test grep call landed normally in the
ledger:

```
verb    n   ok%   p50_exec   p95_exec  p50_out  p95_out  trunc%
grep    1  100%     37.6ms     37.6ms      960      960      0%
```

Same shape as a CLI grep — confirms the MCP path produces ledger rows
indistinguishable from CLI rows. That property is load-bearing for the
recursive-development thesis: MCP adoption immediately starts producing
real-session ledger data without any ledger schema change.
